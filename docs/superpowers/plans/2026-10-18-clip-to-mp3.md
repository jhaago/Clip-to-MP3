# Clip to MP3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver an installable personal Android app that converts short MP4 clips into MP3 entirely offline.

**Architecture:** A native Java Activity observes a retained conversion controller. A worker streams Android-decoded PCM into a small JNI wrapper around LAME, then exposes the completed private MP3 through system Save and Share flows. Keep codec and export resources separate from UI lifetimes.

**Tech Stack:** Java 17; Gradle 8.9; Android Gradle Plugin 8.7.3; compile/target SDK 35; build tools 35.0.0; min SDK 29; NDK 27.2.12479018; CMake 3.22.1; LAME 3.100; platform widgets. Package ARM64 and x86_64 (the latter for emulator validation). The NDK version supports current 16 KB native page alignment; verify the built libraries and APK alignment rather than relying on defaults.

**Spec:** `docs/superpowers/specs/2026-10-18-clip-to-mp3-design.md`

## Global Constraints

- Support Android 10 and later, including ARM64 phones.
- Use fixed 192 kbps output, retaining mono or stereo as appropriate.
- No account, advertising, analytics, internet permission, batch conversion, trimming, or quality settings.
- The source video is never modified.
- Delivery must include an installable APK; source code alone does not meet the goal.
- All media processing happens on the phone.
- Use Android content URIs throughout file selection and export; do not request broad storage access.
- Preserve active conversion across screen rotation; cancel cleanly if the process is destroyed.
- Source delivery excludes private signing material. Preserve that material privately for updates.

## Review Focus

- A content provider returns a nonseekable or unknown-length file: stage input to private disk if required and clean it afterwards.
- Decoder emits float PCM or changes format: convert supported PCM to signed 16-bit; reject incompatible midstream changes cleanly.
- Mono audio or an odd-sized PCM buffer: preserve channels and carry incomplete frames to the next buffer.
- User cancels the save picker or destination write fails: retain finished audio and allow another save attempt.
- User rotates or leaves during conversion: retain one worker, avoid duplicate work, and keep callbacks away from destroyed Activities.

## File map

- `ConversionController.java` in the same package: retained worker state, progress, cancellation and result ownership.
- `AudioConverter.java`: extraction, decode, PCM normalization, timestamp progress and cleanup.
- `PcmFrames.java`: bounded PCM conversion and complete-frame buffering.
- `Mp3Encoder.java`: native handle lifecycle and checked encode/flush calls.
- `OutputFiles.java`: naming, private cache cleanup and content-URI save copying.
- `ShareProvider.java`: narrow read-only provider for completed audio.
- `app/src/main/cpp/{CMakeLists.txt,encoder.c}`: native shared library and JNI wrappers.
- `third_party/lame/`, `THIRD_PARTY_NOTICES.txt`: original LAME source and notices.
- `tests/`: host PCM and encoder checks; `app/src/androidTest/`: device conversion smoke tests.
- `README.md`, `scripts/build.sh`, `scripts/package.sh`: reproducible builds, packaging and phone installation steps.

## Task 1: Native encoder and reproducible build

**Interfaces:** `Mp3Encoder(int sampleRate, int channels)`; `byte[] encode(short[] interleaved, int sampleCount)`; `byte[] finish()`; `void close()`. Implements `AutoCloseable`; rejects invalid channels, sample counts, and use after close. Native code uses per-instance handles, never a global encoder.

- [ ] Obtain the pinned Android toolchain and original LAME 3.100 source, retain upstream notices and record source checksums. Configure the small Java Android project, ABI builds, wrapper and ignore rules; keep tools, private keys and outputs outside tracked source.
- [ ] Write `tests/test_encoder.py`: compile a host harness using the same LAME sources; encode one-second mono and stereo sine fixtures at 44.1 and 48 kHz; assert ffprobe reports `codec_name == mp3`, channel count matches, duration differs by less than 0.15 seconds, and decoded RMS is nonzero. Check zero samples, invalid channel count and final encoder flush handling.
- [ ] Run `python3 tests/test_encoder.py` before adding the wrapper/harness; confirm failure identifies the missing harness.
- [ ] Implement `encoder.c` and `Mp3Encoder.java` with 192 kbps, checked LAME return values, bounded output allocation, native handle release and idempotent close. Avoid writing an MP3 tag that requires seeking; use a valid streaming MP3 output.
- [ ] Run the encoder checks and `./gradlew :app:assembleDebug`; inspect ARM64 and x86_64 ELF alignment. Fix errors before proceeding.
- [ ] Commit the encoder and build foundation.

## Task 2: Streaming conversion and retained state

**Interfaces:** `AudioConverter.convert(Context context, Uri input, File output, Listener listener, AtomicBoolean cancelled)` throws on failure; `Listener.onProgress(int percent)`. `ConversionController` owns a single worker and immutable state snapshots with status, progress, input name, output file and user-readable error. `PcmFrames.accept(ByteBuffer pcm, int encoding)` yields complete signed-16-bit interleaved frames, retaining partial bytes.

- [ ] Write host PCM tests for signed-16-bit, float clamping, mono/stereo, split frames and incompatible format transitions. Assert split-frame output equals unsplit output. Write Android fixture checks for a normal AAC MP4, no-audio MP4, damaged input, cancellation, and nonseekable input staging.
- [ ] Run the host tests and confirm they fail for the missing PCM implementation; run Android checks only once a device/emulator is available and explicitly report if unavailable.
- [ ] Implement `PcmFrames.java`, `AudioConverter.java` and `ConversionController.java`. Drain decoder EOS, respect output offsets/limits, select the first supported audio track, normalize PCM and flush LAME. Reject unsupported channel layouts. Handle absent/zero duration with indeterminate progress. Progress reaches completion only after output closes successfully.
- [ ] Stage nonseekable inputs using bounded copy buffers. Check cancellation during staging, decoding and encoding; release every codec/extractor/descriptor and remove partial output on failure. Use a retained platform Fragment to own the controller across rotation; the worker retains only application context. On true Activity finish cancel and release resources. Process death relies on OS resource release plus next-launch stale-file cleanup.
- [ ] Run host checks and Android fixture checks where possible; verify repeated conversions release resources. Commit conversion components.

## Task 3: Phone UI, saving and sharing

**Interfaces:** `OutputFiles.suggestName(String inputName)` returns a safe `.mp3` name; `OutputFiles.copyTo(Context context, File source, Uri destination)` leaves private completed source intact on failure. `ShareProvider` grants read-only access only to the current completed cache output, with MIME `audio/mpeg`.

- [ ] Write focused naming checks for uppercase `.MP4`, missing extension, blank filename and Unicode. Add device checks for save-picker cancellation, failed destination writes, granted share access, rotation during conversion and repeated Convert taps.
- [ ] Run checks to confirm missing implementation failures, then implement `OutputFiles.java`, `ShareProvider.java` and `MainActivity.java`.
- [ ] Build a simple platform-widget UI: title, offline explanation, selected filename, Choose video, Convert, progress, Cancel, Save MP3, Share and readable status. Disable conflicting controls while converting. Keep the screen awake only during conversion; tell the user to keep the app open.
- [ ] Use system open/create document intents with scoped URI grants. Share via chooser, `ClipData`, and temporary read permission. Make Save and Share available only after successful conversion. Allow another save after cancellation or failure. Bundle license information in an About dialog.
- [ ] Run relevant host and device checks; inspect the installed UI if an emulator is available. Commit the complete user flow.

## Plan self-review

The four tasks cover the approved flow, bounded streaming memory, output cleanup, privacy, licenses, phone-only delivery and truthful testing limits. Each Review Focus case belongs to a named test in Tasks 2 or 3. The controller is the only worker owner, and the Activity consumes snapshots, preventing rotation from starting another conversion. A fresh empty project is already isolated from user code; implementation can proceed in this project checkout without creating another worktree.
